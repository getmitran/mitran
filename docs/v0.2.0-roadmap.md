# Mitran v0.2.0 Roadmap

> **Status:** Planning  
> **Target:** Q3 2026  
> **Theme:** From working demo → production-grade team platform

## What v0.1.0 Delivered

- Go engine + Python workers + React dashboard
- 16 agents (7 focused + 9 legacy)
- SQLite persistence, auth, task dispatcher, SSE streaming
- Memory, cron scheduler, artifacts systems
- Docker Compose deployment
- CI/CD with coverage gates + Trivy security scanning
- "Init Team" onboarding flow

## v0.2.0 Goals

Make Mitran feel like a **real product** that teams adopt and keep using daily.

---

## Phase 1: Agent Intelligence (Weeks 1-3)

### 1.1 PM Agent as Orchestrator
- [ ] PM agent receives natural language goals → decomposes into tasks
- [ ] Auto-assigns tasks to appropriate agents (developer, tester, etc.)
- [ ] Tracks completion, retries failures, escalates blocks
- [ ] Sprint board auto-updates from agent activity

### 1.2 Agent-to-Agent Communication
- [ ] Agents can delegate subtasks to other agents
- [ ] Developer → Tester handoff (code written → tests generated)
- [ ] Architect → Developer handoff (design decisions → implementation tasks)
- [ ] Result aggregation and conflict resolution

### 1.3 Agent Memory Integration
- [ ] Each agent reads/writes project memory (facts + lessons)
- [ ] Agents learn from corrections ("always use Go interfaces for DB access")
- [ ] Cross-session continuity — agent remembers what it did last time

### 1.4 Tool Calling (MCP Support)
- [ ] Agents can call external tools via MCP protocol
- [ ] Git operations (commit, branch, diff)
- [ ] File system read/write
- [ ] HTTP requests to external APIs
- [ ] User-configurable tool approval (auto/interactive)

## Phase 2: Real-Time Experience (Weeks 3-5)

### 2.1 WebSocket Chat (Replace Polling)
- [ ] Bi-directional WebSocket for chat interface
- [ ] Agent streams responses token-by-token
- [ ] Real-time task status updates without polling
- [ ] Multi-user presence awareness

### 2.2 Log Streaming
- [ ] Live agent execution logs in dashboard
- [ ] Per-task log panel (what is agent doing right now?)
- [ ] SSE/WS-based — no more polling GET /tasks/{id}

### 2.3 Notifications
- [ ] Slack notifications for task completion/failure
- [ ] @mention when agent needs human decision

## Phase 3: Production Hardening (Weeks 5-7)

### 3.1 Multi-Tenant Isolation
- [ ] Teams are fully isolated (separate DB schemas or row-level)
- [ ] API keys scoped to team
- [ ] Rate limiting per team
- [ ] Audit log per team

### 3.2 LLM Provider Abstraction
- [ ] Support multiple providers: Bedrock, OpenAI, Ollama, Anthropic direct
- [ ] Per-agent model selection (cheap model for tester, smart for architect)
- [ ] Token budget tracking per team
- [ ] Automatic fallback on provider failure

### 3.3 Proper Authentication
- [ ] JWT with JWKS verification (deferred from v0.1.0)
- [ ] OAuth2/OIDC SSO integration
- [ ] API key management UI
- [ ] Session management with refresh tokens

### 3.4 Database Migration
- [ ] SQLite → PostgreSQL for production deployments
- [ ] Migration tooling (goose or golang-migrate)
- [ ] Connection pooling
- [ ] Backup/restore utilities

## Architecture Changes

```
v0.1.0:  Dashboard → REST API → Go Engine → HTTP POST → Python Worker
v0.2.0:  Dashboard → WebSocket → Go Engine → gRPC → Python Worker(s)
                                     ↓
                              Agent Memory (SQLite/PG)
                              Cron Scheduler
                              MCP Tool Gateway
```

Key difference: gRPC replaces HTTP between engine and workers, enabling streaming, multiplexing, and proper health checks.
